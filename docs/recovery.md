# Recovery runbook

Target RPO is approximately five minutes and target RTO is two hours. These are targets, not demonstrated AWS guarantees. The local emulator drill proves code paths and reconciliation, not service propagation or real restoration speed.

Before launch and quarterly, restore to a **new** `restore-*` table. The administrator-only `scripts/restore.ts` creates an on-demand backup, restores a new table, compares canonical user records, clears/rebuilds only derived records in the new table, and re-enables PITR. It never switches application traffic. Use `node --import tsx scripts/restore.ts SOURCE_TABLE restore-DRILL_ID PRIVATE_ARCHIVE_BUCKET OWNER_IDS...`. Keep real output private. Inspect unprocessed batch writes/reconciliation before switching; do not use a partially rebuilt table.

For a region/account failure, use the latest complete weekly export in the other account's recovery bucket and its manifest. Verify export object checksums and archived legacy objects. Import to new tables in the recovery account, restore copied private archive keys, and update canonical archive references only with a reviewed mapping if the bucket configuration changes. Reconcile transaction projections; propagation can make a just-completed operation require repair. Rebuild derived indexes and weekly counts from retained canonical sessions. Preserve operation/copy receipts.

Recreate expiry GSI, encryption, deletion protection, 35-day PITR, backups, alarms and IAM. Verify all enabled-user and identity bindings. Cognito passwords/credentials cannot be exported: recreate identities, require password reset as necessary, and bind the new issuer/sub to the original internal IDs. Do not create new internal IDs for existing users. Confirm old bindings can no longer authenticate, and test private resource isolation again.

Measure the latest recoverable write time against incident time for RPO, and time the full process through a tested runtime-table switch for RTO. Run real OAuth/API/browser smoke against the restored table before switching. Keep old tables intact until reconciliation and retention review. Write a private drill report with source/target table, export/backup identifiers, canonical checksum/count comparison, derived totals, identity checks, IAM denials, PITR status and measured durations. Close the launch gate only after the real AWS drill succeeds.

Verify weekly export completion, not just its initiation; the hourly monitor reports failed/overdue exports. S3 replication is asynchronous, and pre-existing archive objects may need a batch replication job. Verify those objects explicitly. Application/ordinary deployment roles must be denied recovery reads. Give recovery access only to explicitly designated administrator roles, and test that separation from preprod CI.
